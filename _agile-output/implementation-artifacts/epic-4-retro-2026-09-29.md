- 规格对齐：不再使用生产 `-A`，远程模式默认限制 read/write/net/env/run；健康检查位于 publish 之前。来源：`scripts/entrypoint.sh:62-93`、`.github/workflows/build-and-push.yml:64-112`。

### Review lenses

- **Open finding E4-1 — CI gate invokes the wrong Deno executable by default.** The workflow downloads `./deno` at `.github/workflows/build-and-push.yml:27-33` but invokes `./scripts/release-permission-gate.sh` without `DENO_BIN=./deno` at lines 35-36; the gate defaults to `deno` at `scripts/release-permission-gate.sh:7`. On a runner without a preinstalled Deno binary, the release is classified as environment failure before build. Disposition: fix now in the next change; prevention: make the workflow pass the downloaded binary explicitly or add it to PATH.
- **Open finding E4-2 — image health gate exercises the default local profile only.** Dockerfile does not set `DEPLOYMENT_PROFILE`, and the workflow starts the image without one at `.github/workflows/build-and-push.yml:82-86`; entrypoint defaults to `local-trusted` at `scripts/entrypoint.sh:57`. Therefore the release gate does not prove that the selected `remote-shared` minimum profile starts and serves health. Disposition: defer to a follow-up gate enhancement; prevention: run health checks for each release profile intended for publication.
- Adversarial/edge-case/verification-gap inline review of `e80a4d7^..913a27d` found no additional confirmed issue. No Docker runtime was available in this retrospective, so image-level behavior remains a narrowed evidence scope.
