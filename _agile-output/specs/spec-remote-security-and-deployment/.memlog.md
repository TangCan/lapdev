- (direction) 本轮范围聚焦远程共享安全与最小权限部署，作为已完成平台硬化 Epic 之后的下一阶段实现输入。
- (constraint) 必须继续演进现有 React/Vite、Deno/TypeScript、Rust core 单仓库和单部署单元，不引入微服务拆分。
- (constraint) 远程请求必须经过认证会话、workspace 隔离、capability policy 和审计链路；Origin 检查不能作为唯一授权依据。
- (constraint) 生产部署不得把 Deno -A 或容器全权限作为应用安全边界；权限必须按部署 profile 最小化并可测试。
- (constraint) 秘密不得进入 tracked files、浏览器持久化配置、日志、事件或测试 fixture；AI key 必须按部署模式处理。
- (capability) CAP-1 authenticated remote sessions: authorized users can establish and reconnect sessions bound to a workspace and capability policy; success=unauthenticated, expired, forged and cross-workspace sessions are rejected consistently over HTTP and WebSocket.
- (capability) CAP-2 isolated workspace operations: a remote session can operate only within its assigned workspace and allowed capabilities; success=file, Agent, Git, terminal, LSP and AI requests cannot cross workspace or policy boundaries.
- (capability) CAP-3 constrained command execution: operators can run permitted terminal and subprocess operations under an explicit remote policy; success=disallowed commands, environments, working directories and resource requests are rejected and audited without secret leakage.
- (capability) CAP-4 least-privilege release deployment: maintainers can start and health-check Lapdev under a selected permission profile; success=the release image works with the smallest tested filesystem, network, environment and subprocess permissions and publishes only after the gate passes.
- (assumption) 初始目标仍是可信局域网或受控远程共享，而不是立即支持公网多租户 SaaS；公网部署需要额外身份、租户和密钥托管决策。
- (assumption) 现有后端 capability context、workspace boundary、WebSocket session binding、审计和测试基础可作为本 SPEC 的实现起点。
- (question) 正式认证与会话机制采用什么 provider、token/session 生命周期和撤销策略？
- (question) workspace 隔离模型是每用户单 workspace、共享 workspace 成员模型，还是租户/项目层级隔离？
- (question) 远程终端允许哪些命令、环境变量、网络目标、资源限制和交互模式？
- (question) AI key 在远程模式下由服务端 secret store 管理，还是由部署者注入单租户环境？
- (question) 发布 profile 的最小 Deno/container 权限是否需要支持热加载 LSP、Git 和终端子进程？
- (event) self-validate coherence pass: PASS; capabilities have stable IDs with intent and success, constraints bend deployment and authorization decisions, non-goals and open questions preserve unresolved security choices.
- (event) self-validate preservation pass: PASS; the next-stage scope is grounded in the existing SPEC, architecture spine, research and AGENTS project contract.
- (event) spec finalized: remote security and least-privilege deployment scope is ready for architecture and epic decomposition after open security decisions are resolved.
- (decision) 采用 architecture-lapdev-remote-security-2026-09-29 作为远程安全与最小权限部署的 build substrate；SPEC 保留意图和成功信号，架构 Spine 承载可执行边界与继承不变量。
- (decision) 认证机制确定为受控远程共享 v1 的部署注入访问令牌：服务启动从 LAPDEV_REMOTE_ACCESS_TOKEN 读取一次性 bootstrap secret，成功认证后换取服务端内存中的 opaque session；不引入外部 IdP，不把 token 放入 URL、localStorage 或日志。
- (decision) 浏览器 session cookie 使用 Secure、HttpOnly、SameSite=Lax、Path=/ 和短生命周期；WebSocket 只接受已解析并绑定 principal/workspace/session 的服务端 session，Origin 只作辅助检查。
- (decision) workspace 隔离 v1 采用单部署单 workspace root、单 remote session 绑定一个 workspace；不支持共享 workspace 成员、跨 workspace 切换或公网多租户。
- (decision) remote-shared-v1 默认允许 workspace 内文件和 Agent 能力、只读 Git adapter 和配置好的 LSP adapter；任意终端 shell 默认关闭，必须通过显式 deployment policy 才能开启。
- (decision) 命令策略 v1 不接受 shell 字符串；Git 只允许显式只读子命令集合，LSP 只允许配置文件中的固定可执行文件和 workspace root，所有 cwd、参数、环境和资源限制集中由 CommandPolicy 判定。
- (decision) AI secret v1 由部署环境注入并仅在后端 provider adapter 内使用；不实现外部 secret store，远程客户端只获得已配置/未配置状态，密钥轮换通过重新部署完成。
- (decision) remote-shared-v1 permission profile 显式收窄 Deno/container 文件、网络、环境和进程权限；默认不授予任意 shell，allow-run 只包含固定 Git/LSP 可执行文件，发布门禁验证允许路径和拒绝路径。
- (decision) session store v1 使用后端内存并在进程重启后全部失效；生产部署必须提供 HTTPS/TLS 终止，测试环境可使用明确标记的本地例外。
- (event) security decisions resolved for remote-shared-v1: controlled single-workspace deployment, bootstrap token to opaque session, deny-by-default command policy, server-side environment secrets and explicit permission profile.
