- (direction) 将既有架构 spine distill 为 Lapdev platform hardening and extensibility spec；目标是供后续实现、测试和拆分 stories 使用，不生成额外演示文档。
- (constraint) 必须基于现有 React/Vite、Deno/TypeScript、Rust core 单仓库和单部署现实演进，不把当前系统重写为微服务。
- (constraint) 后端是 workspace/session/file/LSP/skill/agent 状态事实源；前端只拥有视图与临时交互状态；跨模块事件使用统一 versioned envelope。
- (constraint) 所有 privileged operation 必须经 capability context 与 policy profile 授权；本地可信和远程共享模式的认证与部署权限必须分层。
- (constraint) Codex/BMAD 技能主来源是 .agents/skills，.lapdev/skills 只作标记清晰的 legacy source；BMAD 当前输出目录是 _agile-output。
- (capability) CAP-1 canonical runtime and discovery contract: agents and operators can find the current BMAD artifacts, Codex/BMAD skills, runtime commands and version/port contract without guessing; success=clean setup follows one documented path and registry diagnostics explain missing or duplicate sources.
- (capability) CAP-2 governed capability execution: the system can authorize and audit workspace, file, terminal, Git, LSP, AI and Agent operations per user/workspace/session policy; success=unauthorized and workspace-escaping operations are rejected consistently across HTTP and WebSocket.
- (capability) CAP-3 authoritative state and event consistency: clients can reconnect and observe workspace/session changes without competing owners or ambiguous payloads; success=events carry stable identity/revision metadata and stale or duplicate mutations do not silently overwrite newer state.
- (capability) CAP-4 managed extensibility: the system can add skills and language servers through registry/adapter contracts with lifecycle, health and refresh diagnostics; success=adding a source or language does not require duplicating transport, authorization or process-lifecycle logic.
- (capability) CAP-5 deterministic delivery: maintainers can verify implementation, tests, documentation and deployment contracts as one quality signal; success=CI catches command/version/docs drift and separates environment restrictions from real regressions before image release.
- (assumption) 远程共享模式的身份提供商、租户模型、密钥托管和终端命令 allowlist 尚未确定，本 spec 只固定必须存在的 capability/policy boundary。

- (capability) CAP-6 release and local runtime distribution: users can install a versioned npm CLI and start Lapdev without Docker/ACR or manually installing Deno/Rust; success=the CLI selects a supported platform runtime, verifies its manifest/checksum, caches it outside the workspace, starts localhost Lapdev, and retains a source-install path.
- (constraint) 主发布路径采用 npm CLI + GitHub Release platform runtime；Docker/ACR 不再是发布成功门槛，版本 tag 是 CLI 与 runtime 的唯一绑定点。
- (constraint) Runtime manifest 必须绑定 version/platform/arch/asset URL/size/SHA-256/commit；CLI 先临时下载、校验后原子安装到用户缓存，不把 runtime 或 secrets 写入 workspace。
- (constraint) 第一批平台为 linux-x64 与 darwin-arm64；Rust dynamic library 必须按 target 构建并作为 Deno FFI 可加载的真实文件随 archive 分发，默认监听 127.0.0.1。
- (constraint) npm 发布使用 GitHub Actions Trusted Publishing/OIDC；pull request 只构建和测试，受保护 v* tag 才能发布 npm CLI 与 GitHub Release assets。
