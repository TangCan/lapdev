- (direction) Coaching path；唯一交付物为供开发落地的精简 architecture spine，不生成额外团队演示文档。
- (constraint) Brownfield reality: React/Vite frontend, Deno/TypeScript backend, Rust core, WebSocket terminal/file-watch paths, LSP, AI providers, Agent operations, BMAD and skills are already present; the spine must ratify existing code rather than invent a replacement stack.
- (constraint) Current project context is recorded in AGENTS.md; current BMAD artifacts live under _agile-output; current Codex/BMAD skills live under .agents/skills; legacy .lapdev/skills and implementation_artifacts remain compatibility/archive inputs.
- (decision) 采用模块化单体 + capability/ports-and-adapters 范式；Binds=全部后端能力模块；Prevents=各功能自行定义权限、状态和跨边界调用；Rule=保留单一部署单元，但终端、文件、Git、LSP、AI、技能和 WebSocket 必须通过明确的 application service、capability policy 与 adapter 边界接入。
- (decision) 后端作为 workspace/session/file/LSP/skill/agent 操作的事实源，前端只拥有 UI 与临时交互状态；Binds=跨客户端和重连场景的状态同步；Prevents=前后端双重写入、事件乱序和不同模块各自维护真相；Rule=后端为持久/外部状态的唯一 owner，API/WebSocket 事件携带 workspace、session 与 revision 标识，前端通过事件更新视图。
- (decision) 所有请求与 WebSocket 会话必须解析统一 capability context（user/workspace/session/capabilities），再由 policy profile 授权文件、终端、Git、LSP、AI 与技能操作；Binds=本地可信与远程共享两种部署模式；Prevents=HTTP、WebSocket、Agent、LSP 各自鉴权及生产环境仅依赖 Deno -A；Rule=应用层统一拒绝未授权操作并产生日志，部署层使用最小 Deno/容器权限作为第二道边界。
- (decision) 技能通过 SkillRegistry 与来源适配器发现；Binds=Codex/BMAD 与 legacy Lapdev skill integration；Prevents=多目录重复扫描、版本冲突和不可解释的技能不可见；Rule=.agents/skills 是主来源，.lapdev/skills 仅作为标记清晰的兼容来源，注册表负责 SKILL.md 元数据解析、去重、启用状态、刷新错误和调用入口，不复制或改写技能内容。
- (decision) LSP 由后端 LSP Manager 按 workspace/session 管理进程；Binds=LSP 与前端编辑器、文件监听、诊断和语言 adapter；Prevents=各 handler 重复实现进程生命周期、取消、能力协商和崩溃恢复；Rule=前端只能通过后端 LSP capability 使用协议，语言差异位于 adapter/config，Manager 统一生命周期、诊断 revision、健康状态和资源回收。
- (decision) 所有跨模块 API/WebSocket 事件采用统一 versioned envelope；Binds=文件、终端、LSP、Agent、技能和 AI 事件；Prevents=各模块 payload、错误、重连和版本兼容规则不一致；Rule=事件至少携带 type、version、workspaceId、sessionId、revision、requestId 与统一 error shape，业务 payload 由 capability 定义，后端负责顺序、幂等和重放边界。
- (version) 实现基线：React 19.2.x、Vite 6.x、TypeScript 5.5.x、Vitest 2.0.5、Playwright 1.60.0、Deno 2.8.2（CI DENO_VERSION）、Rust edition 2021；版本来自 package manifests、CI 和 Cargo manifest，不代表最新版本。
- (assumption) 当前 spine 先覆盖现有单仓库、单部署单元的 platform architecture；公网多用户的身份提供商、租户模型和密钥托管尚未确定，不在本次 spine 中虚构。
- (question) 需要在实现安全 profile 时确定本地可信模式与远程共享模式的具体认证机制、workspace 隔离策略和终端命令 allowlist。
